Project Files and Folders

Simple explanation guide for the AWS Docker Deployment Platform

What this project does: Terraform prepares an AWS network and application platform. Internet traffic enters through an Application Load Balancer. Docker application instances run inside private subnets and scale using an Auto Scaling Group. The application can use private RDS PostgreSQL and Redis services. GitHub Actions checks Terraform and can build/deploy an application after its source and Dockerfile are supplied.

GitHub automatically reads workflow files from this folder.

FileWhat it containsWhy it is used

Why deployment may show “Skipped”

The assignment did not include the black-box application source or a Dockerfile. The workflow checks for a root Dockerfile. If it is absent, app_available=false; the AWS build and deploy stages are skipped instead of pretending that an application was deployed.

7. AWS infrastructure — infra/aws/

Terraform reads all .tf files in this directory together. File names organize the code for humans; they do not change Terraform execution order.

FileWhat it containsWhy it is used
versions.tfTerraform version requirement, AWS and Random provider versions, S3 remote-state backend declaration, AWS region and common tags.It makes tool/provider requirements clear and prepares safe shared remote state.
variables.tfInputs such as project name, environment, region, CIDR, image URI, instance sizes, ASG limits, database size and Redis size.The same Terraform code can be reused for development, staging and production without rewriting resources.
terraform.tfvars.exampleExample values for every important variable.Copy it to terraform.tfvars and replace the examples. The real file stays ignored by Git.
main.tfAvailability Zones, VPC, two public subnets, two private app subnets, two private DB subnets, IGW, NAT, route tables and security groups.This creates the network foundation and controls which components can communicate.
compute.tfAmazon Linux AMI lookup, EC2 IAM role/profile, ECR/SSM/secret permissions, ALB, target group, listener, launch template, ASG and scaling policy.This runs Docker application instances, distributes traffic, replaces unhealthy instances and scales capacity.
data.tfRandom database password, Secrets Manager secret, RDS subnet group/PostgreSQL instance, Redis subnet group and replication group.This creates private managed data services and avoids hardcoding a database password.
outputs.tfUseful results such as ALB DNS name, VPC ID, private subnet IDs and database secret ARN.It displays values needed after deployment or by other automation.
.terraform.lock.hclExact provider versions and checksums selected by terraform init.It makes provider installation repeatable and should normally be committed.

11. Simple deployment sequence

  1. Copy terraform.tfvars.example to terraform.tfvars and enter correct values.
  2. Configure the S3 state bucket, DynamoDB lock table and AWS credentials.
  3. Run terraform init, terraform plan and terraform apply.
  4. Terraform creates networking, security, ALB, Auto Scaling, RDS and Redis.
  5. When real application source and a root Dockerfile are available, the build workflow scans and pushes the image to ECR.
  6. The workflow deploys the image digest; ASG replaces instances gradually and the ALB sends traffic only to healthy targets.
  7. Run scripts/check-health.ps1 with the ALB DNS name and save only real, sanitized evidence.
